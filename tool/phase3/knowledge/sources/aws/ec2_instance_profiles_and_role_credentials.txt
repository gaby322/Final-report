EC2 Instance Profiles and Role Credentials
Type: Curated synthesis from AWS official documentation
Source: AWS IAM and Amazon EC2 official documentation

Overview:
Applications running on an EC2 instance can use temporary AWS credentials from an IAM role attached to that instance. AWS makes this possible through an instance profile associated with the EC2 instance.

Key points:
- An EC2 instance uses an instance profile to receive an IAM role
- Only one role can be attached to an EC2 instance at a time
- Applications on the instance can obtain temporary credentials from the Instance Metadata Service (IMDS)
- AWS recommends roles and temporary credentials instead of long-term access keys on EC2 instances

Credential retrieval:
AWS documents that applications and tools running on the instance can retrieve temporary credentials from instance metadata. These credentials are automatically rotated by AWS.

Security relevance:
If a principal can influence which role is associated with an EC2 instance, and can also access the instance or workload, that principal may gain the effective permissions of the attached role through the instance environment.

IAM relevance:
Instance profiles are operationally important to IAM security because they connect:
- role attachment
- role passing
- EC2 execution context
- temporary credential availability

Relationship to this framework:
This framework uses EC2 instance-profile and role-credential behavior to explain service-mediated privilege-escalation paths such as PassRole via EC2 and AddRoleToInstanceProfile-driven transitions.
