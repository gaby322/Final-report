# actions: CreateAccessKey,CreateLoginProfile,sts:GetFederationToken

Technique: T1098.001 — Account Manipulation: Additional Cloud Credentials
Tactics: Persistence, Privilege Escalation
Platforms: IaaS, Identity Provider, SaaS

Source: MITRE ATT&CK
URL: https://attack.mitre.org/techniques/T1098/001/

Description:
Adversaries may add adversary-controlled credentials to a cloud account to maintain persistent access to victim accounts and instances within the environment. In AWS, MITRE notes examples such as using CreateAccessKey to add access keys to an account, CreateLoginProfile to add a console password, and sts:GetFederationToken to create temporary credentials tied to the original user account. In IaaS contexts, MITRE also notes CreateKeyPair and ImportKeyPair for persistent access to instances.

AWS procedure examples noted by MITRE:
- CreateAccessKey to add access keys to an account
- CreateLoginProfile to add a console password
- sts:GetFederationToken to create temporary credentials
- CreateKeyPair / ImportKeyPair for instance access in IaaS contexts

Detection:
MITRE’s detection strategy focuses on addition of credentials to existing cloud accounts via portal or API by non-standard identities or IP ranges, and on cloud API usage such as CreateAccessKey, ImportKeyPair, or CreateLoginProfile from unusual principals or non-console access patterns.

Mitigation:
MITRE mitigation guidance includes using multi-factor authentication for user and privileged accounts, ensuring low-privileged users cannot add access keys to accounts, and prohibiting sts:GetFederationToken unless explicitly required.

Framework note:
In this framework, AWS IAM / STS events aligned with T1098.001 may be used as retrieval and correlation evidence in Phase 3. Any final alert prioritization remains framework-specific and is not a MITRE severity claim.
